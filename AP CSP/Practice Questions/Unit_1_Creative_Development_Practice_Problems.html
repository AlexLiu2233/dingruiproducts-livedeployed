Q1MEDIUMAP MC1.1 Collaboration[1]

A team is designing a bus arrival app. Its initial prototype assumes that everyone can read small text and has a reliable Internet connection.一个团队正在设计公交到站应用程序。其初始原型（prototype）假设所有人都能阅读小字号文字，并且都有可靠的互联网连接。

Which action is most likely to improve the app by incorporating diverse perspectives?以下哪项行动最可能通过纳入不同视角来改进该应用程序？

  • (A) Ask only the developers to evaluate the existing interface.仅让开发者评估现有界面。
  • (B) Add more features before asking anyone for feedback.在征求任何人反馈之前添加更多功能。
  • (C) Observe and interview potential users with different visual and connectivity needs.观察并访谈在视觉和网络连接方面有不同需求的潜在用户。
  • (D) Choose the interface preferred by the team leader without testing it.不经测试，选择团队负责人偏好的界面。

Q6HARDAP MC1.2 Program Function and Purpose[1]

An art app waits for the user to tap a color button. The tap causes the app to read the selected color and change the color displayed on the canvas.一个绘画应用程序等待用户点击颜色按钮。点击后，应用程序读取所选颜色，并改变画布上显示的颜色。

Which description correctly identifies the event, input, and output?以下哪项正确识别了事件（event）、输入（input）和输出（output）？

  • (A) The displayed color is the event; the tap is the output; the selected color is the input.显示的颜色是事件；点击是输出；所选颜色是输入。
  • (B) The tap is output; the changed canvas is input; the selected color is the event.点击是输出；改变后的画布是输入；所选颜色是事件。
  • (C) The selected color is output; the canvas is the event; the tap is a stored procedure.所选颜色是输出；画布是事件；点击是一个存储的过程。
  • (D) The tap is the event; the selected color supplies input; the changed canvas is visual output.点击是事件；所选颜色提供输入；改变后的画布是视觉输出。

Q8MEDIUMAP MC1.3 Program Design and Development[1]

A team builds a basic appointment app, tests it with users, revises the scheduling screen, and tests the revised screen again.一个团队先构建基本的预约应用程序，再让用户测试，根据反馈修改预约界面，然后再次测试修改后的界面。

Which description best characterizes this development process?以下哪项最能描述这一开发过程？

  • (A) A single-pass process, because testing occurs after implementation.单次过程，因为测试发生在实现之后。
  • (B) A process without investigation, because users participate.没有调查的过程，因为用户参与了其中。
  • (C) Iterative, because feedback leads to repeated revision and testing.迭代式，因为反馈促使团队反复修改和测试。
  • (D) A guarantee of correctness, because the screen was tested twice.保证正确的过程，因为界面经过了两次测试。
Q9HARDAP MC1.3 Program Design and Development[1]

A developer maintains a program that calculates library fines. A comment says that a procedure returns a fine in cents, but the procedure was recently changed to return dollars.一位开发者维护一个计算图书馆罚款的程序。一条注释（comment）说明某过程返回以分为单位的罚款，但该过程最近已改为返回以元为单位的金额。

Which action best supports future maintenance?以下哪项行动最有利于今后的维护？

  • (A) Leave the comment unchanged because comments control the returned unit.保留原注释，因为注释控制返回值的单位。
  • (B) Update the documentation to describe the current returned unit and check code that uses the result.更新文档，说明当前返回值的单位，并检查使用该结果的代码。
  • (C) Delete all documentation so that no comment can become outdated.删除所有文档，这样就不会有过时的注释。
  • (D) Change only the comment and assume the program's behavior will change to match it.只修改注释，并假定程序行为会随之改变。

Q14HARDAP MC1.4 Identifying and Correcting Errors[1]

A procedure is intended to sum the positive even integers up to and including its parameter. A developer tests it with 8.一个过程（procedure）旨在求出不超过其参数的所有正偶数之和，包含参数本身。一位开发者使用 8 进行测试。

PROCEDURE sumEven(limit) {
  i ← 1
  total ← 0
REPEAT UNTIL(i > limit) {
    IF(i MOD 2 = 0) {
      total ← total + i
    }
    i ← i + 1
  }
  RETURN(total)
}
DISPLAY(sumEven(8))

What value does this test display?此次测试显示什么值？

  • (A) 12
  • (B) 20
  • (C) 16
  • (D) 36
