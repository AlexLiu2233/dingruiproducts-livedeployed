Object-Oriented Programming (Intro)面向对象编程（入门）

Object-oriented programming (OOP) is a way of organising code around objects, bundles that combine data (attributes) and behaviour (methods) into a single unit. You define a class as the blueprint, then create as many instances as you need. A Dog class describes what every dog has and can do; each individual dog (Fido, Bella) is a separate object. This guide covers Python OOP from scratch: defining classes, writing instance variables, calling methods, building constructors with __init__, and a first look at encapsulation and inheritance. All code is Python; it feeds directly into AP CSA Java classes.面向对象编程（OOP，object-oriented programming）是一种将代码围绕对象（object）组织的方式，对象将数据（属性 attribute）和行为（方法 method）捆绑为一个单元。你把类（class）定义为蓝图，然后按需创建任意数量的实例（instance）。Dog 类描述每条狗拥有什么、能做什么；每条具体的狗（Fido、Bella）是独立的对象。本指南从零开始讲授 Python OOP：定义类、编写实例变量、调用方法、用 __init__ 构建构造函数（constructor），以及初步了解封装（encapsulation）与继承（inheritance）。全部代码为 Python，直接为 AP CSA Java 类打基础。

Worked Example 1: Comparing procedural vs OOP style例题 1：过程式与面向对象风格对比

Model two dogs (Fido age 3, Bella age 5). Show the difference between procedural (separate variables) and OOP (class instance) approaches.建模两条狗（Fido 3 岁，Bella 5 岁）。展示过程式（分散变量）与面向对象（类实例）方式的区别。

Procedural approach (messy, hard to scale).过程式方式（混乱，难以扩展）。

dog1_name = "Fido"
dog1_age  = 3
dog2_name = "Bella"
dog2_age  = 5

Procedural: each dog needs multiple separate variables; the code grows out of control as the number of dogs increases.过程式：每条狗需要多个独立变量，数量增加时代码迅速失控。

OOP approach (clean, scalable).面向对象方式（简洁，可扩展）。

class Dog:
    def __init__(self, name, age):

        self.age  = age

fido  = Dog("Fido",  3)

Worked Example 2: One object, two names (aliasing)例题 2：一个对象，两个名字（别名）

Create two Dog objects with identical data and a third name for the first. Show whether they are equal, whether they are the same object, and what happens when you change the age through the third name.创建两个数据完全相同的 Dog 对象，再给第一个对象起第三个名字。说明它们是否相等、是否为同一对象，以及通过第三个名字修改年龄会发生什么。

class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age  = age

a = Dog("Rex", 4)
b = Dog("Rex", 4)
c = a                       # c is another name for the same object

print(a == b, a is b, a is c)   # False False True
c.age = 5
print(a.age, b.age)             # 5 4
print(isinstance(a, Dog), isinstance("Rex", Dog))   # True False

a and b hold the same data, but Dog("Rex", 4) ran twice and built two objects. A class with no __eq__ method compares by identity, so a == b is False and a is b is False. The line c = a does not build anything: it gives the existing object a second name, so a is c is True. Changing c.age changes the one shared object, which is why a.age becomes 5 while b.age stays 4.a 和 b 的数据相同，但 Dog("Rex", 4) 运行了两次，造出了两个对象。没有定义 __eq__ 方法的类按同一性比较，所以 a == b 为 False，a is b 也为 False。c = a 不会造新对象，只是给已有对象起第二个名字，所以 a is c 为 True。修改 c.age 改的是那个共享的对象，因此 a.age 变为 5，而 b.age 仍是 4。

isinstance(obj, Class) asks whether the object was built from that class (or from a subclass of it). isinstance(a, Dog) is True; a string is not a Dog, so the second test is False.isinstance(对象, 类) 检查对象是否由该类（或其子类）创建。isinstance(a, Dog) 为 True；字符串不是 Dog，所以第二个检验为 False。

Worked Example 3: A Student class例题 3：Student 类

Define a Student class with a name and a grade (0–100). Add a method is_passing() that returns True if grade ≥ 50.定义一个 Student 类，包含姓名和成绩（0–100）。添加方法 is_passing()，如果成绩 ≥ 50 则返回 True。

class Student:
    def __init__(self, name, grade):
        self.name  = name
        self.grade = grade

    def is_passing(self):
        return self.grade >= 50

# Create two instances
s1 = Student("Alice", 78)
s2 = Student("Bob",   42)

print(s1.name, s1.is_passing())   # Alice True
print(s2.name, s2.is_passing())   # Bob   False

Worked Example 4: Printing an object: __str__ and __repr__例题 4：打印对象：__str__ 与 __repr__

Give the Student class a readable text form for print and an unambiguous form for debugging. Show what print(s), print([s]) and repr(s) display, and show that Student.is_passing(s) and s.is_passing() are the same call.为 Student 类提供供 print 使用的易读文本形式和供调试用的明确形式。展示 print(s)、print([s]) 和 repr(s) 的显示结果，并说明 Student.is_passing(s) 与 s.is_passing() 是同一个调用。

class Student:
    def __init__(self, name, grade):
        self.name  = name
        self.grade = grade

    def __str__(self):                 # readable, for print(s) and str(s)
        return f"{self.name} ({self.grade})"

    def __repr__(self):                # unambiguous, for repr(s) and lists
        return f"Student({self.name!r}, {self.grade})"

    def is_passing(self):
        return self.grade >= 50

s = Student("Alice", 78)
print(s)                                # Alice (78)
print([s])                              # [Student('Alice', 78)]
print(repr(s))                          # Student('Alice', 78)
print(Student.is_passing(s) == s.is_passing())   # True

print(s) calls __str__, so it shows the friendly text Alice (78). A list does not use __str__ for its items: it shows each item with __repr__, so print([s]) gives [Student('Alice', 78)]. The !r inside the f-string asks for the repr of the name, which is why the name appears in quotes. If a class defines neither method, print(obj) shows a default such as <__main__.Student object at 0x...>, whose address differs on every run.print(s) 调用 __str__，所以显示友好的文本 Alice (78)。列表显示其元素时不用 __str__，而用 __repr__，所以 print([s]) 得到 [Student('Alice', 78)]。f 字符串中的 !r 要求取姓名的 repr，因此姓名带引号。如果类两个方法都没定义，print(obj) 显示默认形式，如 <__main__.Student object at 0x...>，其地址每次运行都不同。

The last line shows what self is: s.is_passing() is shorthand for Student.is_passing(s). Python looks up the method in the class and passes s as the first argument, which the method names self.最后一行说明了 self 是什么：s.is_passing() 是 Student.is_passing(s) 的简写。Python 在类中查找方法，并把 s 作为第一个实参传入，方法把它命名为 self。

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner    = owner
        self._balance = balance          # leading underscore: private by convention

    def deposit(self, amount):
        if amount > 0:
            self._balance += amount

    def withdraw(self, amount):
        if 0 < amount <= self._balance:
            self._balance -= amount

    def get_balance(self):
        return self._balance

    def __str__(self):
        return f"{self.owner}: {self._balance}"


class SavingsAccount(BankAccount):
    MIN_BALANCE = 100                    # class attribute shared by all savings accounts

    def __init__(self, owner, balance, rate):
        super().__init__(owner, balance) # let the parent set owner and _balance
        self.rate = rate

    def add_interest(self):
        self._balance += self._balance * self.rate

    def withdraw(self, amount):          # overrides BankAccount.withdraw
        if self._balance - amount >= self.MIN_BALANCE:
            super().withdraw(amount)     # reuse the parent's checks and update

accounts = [BankAccount("Bob", 500), SavingsAccount("Alice", 500, 0.05)]
for acc in accounts:
    acc.withdraw(450)                    # same call, different method runs
    print(acc)
# Bob: 50
# Alice: 500

print(isinstance(accounts[1], BankAccount), isinstance(accounts[0], SavingsAccount))   # True False
print(type(accounts[1]).__name__)        # SavingsAccount

sv = SavingsAccount("Cy", 1000, 0.05)
sv.add_interest()
print(sv.get_balance())                  # 1050.0

class Vault:
    def __init__(self):
        self.__code = 42                 # double underscore: name mangling

v = Vault()
print(hasattr(v, "__code"))              # False
print(v._Vault__code)                    # 42
print(list(vars(v)))                     # ['_Vault__code']

Polymorphism: the loop calls acc.withdraw(450) on both objects, and Python runs the version that belongs to each object's own class. Bob's plain BankAccount allows it (500 becomes 50). Alice's SavingsAccount would drop to 500 - 450 = 50, below MIN_BALANCE 100, so its overriding withdraw refuses and her balance stays 500. When the minimum is respected, the override calls super().withdraw(amount) so the parent's validation and update are reused rather than copied.多态：循环对两个对象都调用 acc.withdraw(450)，Python 运行的是各对象自己所属类的那个版本。Bob 的普通 BankAccount 允许取款（500 变为 50）。Alice 的 SavingsAccount 取款后会降到 500 - 450 = 50，低于 MIN_BALANCE 的 100，所以覆盖后的 withdraw 拒绝执行，她的余额保持 500。当满足最低余额时，覆盖方法调用 super().withdraw(amount)，复用父类的验证和更新，而不是复制代码。

isinstance(accounts[1], BankAccount) is True because a SavingsAccount is a BankAccount (the is-a relationship), but a plain BankAccount is not a SavingsAccount, so the second test is False. add_interest gives 1000 + 1000 × 0.05 = 1050.0 (a float).isinstance(accounts[1], BankAccount) 为 True，因为 SavingsAccount 是（is-a）BankAccount；但普通的 BankAccount 不是 SavingsAccount，所以第二个检验为 False。add_interest 的结果是 1000 + 1000 × 0.05 = 1050.0（浮点数）。

Name mangling: inside the class, self.__code is stored under the name _Vault__code, so hasattr(v, "__code") is False but v._Vault__code still works. The double underscore prevents accidental clashes with a subclass attribute; it is not a security feature, and a single underscore is the usual way to say "internal, please use the methods".名称改写：在类内部，self.__code 实际存在名字 _Vault__code 之下，所以 hasattr(v, "__code") 为 False，而 v._Vault__code 仍然可以访问。双下划线用来避免与子类属性意外重名，它不是安全机制；表达"内部使用，请通过方法访问"的常用方式是单下划线。

Common Questions常见问题

What is the difference between a class and an object?类和对象有什么区别？

A class is the blueprint or template that defines the attributes and methods shared by all objects of that type, while an object is a concrete instance created from that class. For example, Dog is the class and your specific dog is an object.类是蓝图或模板，定义该类型所有对象共有的属性和方法；对象是由该类创建出来的具体实例。例如，Dog 是类，而你那只具体的狗是对象。

What does __init__ do in a Python class?Python 类中的 __init__ 是做什么的？

__init__ is the constructor, a special method that Python calls automatically when you create a new object. Its job is to assign starting values to all the object's instance attributes, and the double underscores tell Python it is a special method you should never rename.__init__ 是构造方法，一个在你创建新对象时由 Python 自动调用的特殊方法。它的任务是给对象的所有实例属性赋初始值，双下划线告诉 Python 这是一个永远不应改名的特殊方法。

What is encapsulation in object-oriented programming?面向对象编程中的封装是什么？

Encapsulation means keeping an object's data private and exposing it only through methods, so other code interacts with the object through a controlled interface rather than touching its internal state directly. This protects the data and makes programs easier to maintain.封装是指把对象的数据保持为私有，只通过方法对外暴露，使其他代码通过受控的接口与对象交互，而不是直接接触其内部状态。这能保护数据并让程序更易维护。

OOP is an advanced / optional topic across all four curricula at the high-school foundations level. If you are taking ICS4U (Ontario Grade 12), CSE3120 (Alberta Advanced), or Computer Programming 12 (BC), this guide is core material. If you are on the AP CSA track, this guide is the Python warm-up before the Java class-creation unit. If you are in ICS3U, AP CSP, or CSE1110, OOP is not part of your course; bookmark this for later. All code in this guide is Python. The seven sections build in order: you need §1 (what OOP is) before §2 (defining a class) before §5 (constructors).在所有四个课程体系的高中基础级别，OOP 都是进阶/可选主题。如果你正在学习 ICS4U（安大略 12 年级）、CSE3120（阿尔伯塔进阶）或 Computer Programming 12（BC），本指南是核心内容。如果你在 AP CSA 轨道，本指南是进入 Java 类创建单元之前的 Python 热身。如果你在 ICS3U、AP CSP 或 CSE1110，OOP 不在你的课程范围内，先收藏，待以后使用。本指南中所有代码均为 Python。七个章节按顺序递进：需先掌握 §1（OOP 是什么）再学 §2（定义类），再学 §5（构造函数）。

If you are cramming the night before如果你在临阵磨枪

Memorise five things: class = blueprint, object = instance; __init__ is the constructor; self refers to the current object; attributes are per-instance variables; methods are functions inside the class. Read every cram-cheat box. The flashcards cover exam vocabulary cold.背熟五件事：类 = 蓝图，对象 = 实例；__init__ 是构造函数；self 指当前对象；属性是每个实例的变量；方法是类内部的函数。读每个速记框。闪卡涵盖考试词汇的冷知识。

*
If you are going for the top mark如果你目标顶分

Work through every worked example by typing the code yourself and running it. Predict the output before you run it. For §7 (encapsulation), understand why hiding data behind methods is a design benefit, not just what it is. The going-deeper box in §7 introduces inheritance. AP CSA itself stops at class creation (Unit 3), so treat inheritance as a preview.亲手输入并运行每个例题代码。运行前预测输出。对于 §7（封装），理解为什么将数据隐藏在方法后面是设计上的优点，而不仅仅是它是什么。§7 的深入框介绍继承。AP CSA 本身止于类的创建（第 3 单元），所以请把继承当作预习。

Prerequisite note.前置说明。 This guide assumes you can write basic Python functions (def, return, parameters). If you have not yet studied functions, complete the HS CS Functions and Modular Design guide first. AB CSE3120 requires CSE2110 (Procedural Programming 1) as a prerequisite; the same underlying principle.本指南假定你已能编写基本 Python 函数（def、return、参数）。如果尚未学过函数，请先完成 HS CS 函数与模块化设计指南。AB CSE3120 要求 CSE2110（过程式编程 1）作为前置，同样的底层原则。
