Functions and Modular Design函数与模块化设计

Functions are the core tool for writing reusable, readable, and maintainable code. Instead of copying the same logic in five places, you define it once as a named function and call it wherever you need it. This guide builds every concept from scratch: what a function is and why you need one; how to define and call functions; how parameters and arguments let you pass data in; how return values send results out; how variable scope controls which names are visible where; how modular design organises a whole program as a network of cooperating functions; and how built-in functions and libraries save you from reinventing the wheel. All examples use pseudocode and Python side by side.函数（function，函数）是编写可复用、可读性强、易于维护代码的核心工具。与其在五个地方复制同一段逻辑，不如将其定义为一个具名函数（named function，具名函数），在需要时调用（call，调用）。本指南从零开始建立每个概念：函数是什么以及为何需要它；如何定义和调用函数；形参（parameter，形参）和实参（argument，实参）如何让你传入数据；返回值（return value，返回值）如何将结果传出；作用域（scope，作用域）如何控制哪些名称在哪里可见；模块化设计（modular design，模块化设计）如何将整个程序组织为协作函数的网络；以及内置函数（built-in function，内置函数）和库（library，库）如何避免重复造轮子。所有示例均同时使用伪代码和 Python 演示。

Why Functions? Reuse and Abstraction为什么要用函数？复用与抽象

Learning objectives学习目标
  • State three reasons to use a function: reuse, abstraction and decomposition.
  • Rewrite repeated code as one function and call it from each place.
  • Explain why a caller needs only a function's name, inputs and output, not its body.
  • Count how many edits a rule change needs with and without a function.
  • 说出使用函数的三个理由：复用、抽象和分解。
  • 把重复的代码改写为一个函数，并在每个位置调用它。
  • 解释为什么调用方只需要知道函数的名称、输入和输出，而不需要知道函数体。
  • 数出有函数和没有函数时，规则改变各需要多少处修改。
Three reasons to use a function, memorise these.使用函数的三个理由, 背熟这些。
  • Reuse复用: define the logic once; call it anywhere. No copy-paste. If the logic changes, you change one place and all callers get the fix. CSTA 3A-AP-18: "Create artifacts by using procedures within a program.", 定义逻辑一次，在任何地方调用。无需复制粘贴。如果逻辑需要更改，只需修改一处，所有调用方都获得修复。CSTA 3A-AP-18："通过在程序中使用过程来创建制品。"
  • Abstraction抽象: the caller only needs to know what the function does (its name, inputs, output), not how it does it. This hides complexity and lets you think at a higher level. AP CSP Computational Thinking Practice 3.B: "Use abstraction to manage complexity in a program.", 调用方只需知道函数做什么（名称、输入、输出），而不需要知道如何做。这隐藏了复杂性，让你在更高层次上思考。AP CSP 计算思维实践 3.B："使用抽象管理程序中的复杂性。"
  • Decomposition分解: split a big program into small, independently testable functions. Each function solves one clearly-named sub-problem. CSTA 3A-AP-17: "Decompose problems into smaller components … using constructs such as procedures, modules.", 将大型程序拆分为小型、可独立测试的函数。每个函数解决一个命名清晰的子问题。CSTA 3A-AP-17："通过使用过程、模块等构造将问题分解为更小的组件。"
The one fact that catches people: a function is an abstraction, not just a shortcut. When you call math.sqrt(9) you do not need to know the algorithm inside, you just trust the interface. Building your own functions gives the same benefit to whoever calls yours.最易踩坑的一点：函数是一种抽象，不仅仅是快捷方式。当你调用 math.sqrt(9) 时，你不需要知道内部算法，只需信任接口。构建自己的函数，就能给调用者带来同样的好处。

Repeated-code version (bad).重复代码版（不好）。

-- Place 2

-- Place 3

Three places repeat the same logic (width × height). If the formula needs to change, you must edit three places.三处代码重复相同逻辑（宽 × 高）。如需改为"宽 × 高 × 比例因子"，必须修改三处。

Function version (good).函数版（好）。

FUNCTION rectangle_area(width, height):

area2 = rectangle_area(8, 4)   # 32
area3 = rectangle_area(12, 7)  # 84

Worked Example 2: Changing a rule in one place例题 2：只在一处修改规则

Problem: a shop adds 13 percent tax at the till, on the receipt and on the web page. Show the code with the formula copied three times, then as one function, and show what has to change when the rate becomes 15 percent. Use the prices 20.00, 8.00 and 50.00.问题：一家商店在收银台、收据和网页上都要加 13% 的税。展示把公式复制三次的代码，再展示改成一个函数的代码，并说明税率变为 15% 时需要修改什么。使用价格 20.00、8.00 和 50.00。

Pseudocode.伪代码。

-- Version A: the formula is copied into each place
SET till    TO ROUND(20.00 * 1.13, 2)
SET receipt TO ROUND(8.00 * 1.13, 2)
SET web     TO ROUND(50.00 * 1.13, 2)

-- Version B: the formula lives in one function
FUNCTION with_tax(price):
    RETURN ROUND(price * 1.13, 2)
END FUNCTION

SET till    TO with_tax(20.00)
SET receipt TO with_tax(8.00)
SET web     TO with_tax(50.00)

Version A repeats the tax formula three times. When the rate changes you must find and edit every copy, and missing one gives two different prices for the same item. In version B the formula appears once; each caller only writes the function name and the price.版本 A 把税率公式重复了三次。税率改变时必须找到并修改每一处副本，漏掉一处就会让同一商品出现两个不同价格。在版本 B 中公式只出现一次；每个调用方只需写出函数名和价格。

Python rendering.Python 实现。

def with_tax(price):
    return round(price * 1.13, 2)

print(with_tax(20.00))   # 22.6
print(with_tax(8.00))    # 9.04
print(with_tax(50.00))   # 56.5

Each result is the price times 1.13, rounded to 2 decimal places: 20.00 × 1.13 = 22.6, 8.00 × 1.13 = 9.04, 50.00 × 1.13 = 56.5. Python prints 22.6, not 22.60, because a float does not keep trailing zeros.每个结果都是价格乘以 1.13 后保留 2 位小数：20.00 × 1.13 = 22.6，8.00 × 1.13 = 9.04，50.00 × 1.13 = 56.5。Python 输出 22.6 而不是 22.60，因为浮点数不保留末尾的零。

The rate changes to 15 percent.税率改为 15%。

def with_tax(price):
    return round(price * 1.15, 2)   # the only line that changed

print(with_tax(20.00))   # 23.0
print(with_tax(8.00))    # 9.2
print(with_tax(50.00))   # 57.5

Only one line was edited, and every caller is correct without being touched. The callers never needed to know the formula, only the name with_tax and what it returns: that is abstraction. Why this works: a function gives one rule one home, so a change to the rule is one edit.只修改了一行，所有调用方都无需改动就得到正确结果。调用方从来不需要知道公式，只需要知道名称 with_tax 和它返回什么：这就是抽象。原因：函数让一条规则只有一个存放位置，所以规则改变只需一次修改。

Exam tip考试提示

When a question says explain why a function helps, tie the reason to the code you are given: “the tax formula is written three times, so a change needs three edits; a function needs one.” A bare “it is neater” is an incomplete answer. Do not write that functions make a program run faster: a function call does not make a program faster.

当题目要求解释函数的好处时，要把理由和所给代码联系起来：“税率公式写了三次，所以改动需要修改三处；使用函数只需修改一处。”只写“更整洁”是不完整的答案。不要写函数使程序运行更快：调用函数并不会让程序更快。

Going deeper, procedural abstraction and the “black box” model深入, 过程抽象与"黑盒"模型

Computer scientists describe functions using a black box model: inputs go in, outputs come out, and the internal implementation is hidden. This separation of interface (what the function promises) from implementation (how it does it) is what allows large teams to build large systems: one developer writes sort_list(data); every other developer can use it without understanding the sorting algorithm. BC Computer Programming 12 names this "Management of complexity." Ontario ICS4U C1.3 formalises it as "functional decomposition in subprogram design." Alberta CSE2110 outcome 1.1.5 notes "hiding or protecting the program data" as an advantage of modular programming. The principle scales from a 20-line student project to a million-line operating system.计算机科学家使用黑盒模型描述函数：输入进去，输出出来，内部实现被隐藏。接口（函数承诺做什么）与实现（如何做到）的分离，使大型团队能够构建大型系统：一个开发者编写 sort_list(data)；其他所有开发者都可以使用它而无需理解排序算法。BC Computer Programming 12 将此称为"复杂性管理"。安大略 ICS4U C1.3 将其正式化为"子程序设计中的函数分解"。阿尔伯塔 CSE2110 结果 1.1.5 指出"隐藏或保护程序数据"是模块化编程的优势。这个原则适用范围从 20 行的学生项目到百万行的操作系统。

Defining and Calling Functions定义与调用函数

Learning objectives学习目标
  • Distinguish a function definition from a function call.
  • State that a definition stores the body without running it.
  • Trace the order in which lines run when one function calls another.
  • Explain why calling a function before its def line has run gives a NameError.
  • 区分函数定义与函数调用。
  • 说明定义只存放函数体而不运行它。
  • 追踪一个函数调用另一个函数时各行的运行顺序。
  • 解释为什么在 def 行运行之前调用函数会产生 NameError。
Two halves of a function, know both.函数的两个部分, 两者都要掌握。
  • Definition (FUNCTION keyword)定义（FUNCTION 关键字）: creates the named block of code. In pseudocode: FUNCTION name(params): ... END FUNCTION. In Python: def name(params): .... Defining a function does NOT run it., 创建具名代码块。伪代码：FUNCTION name(params): ... END FUNCTION。Python：def name(params): ...。定义函数不会运行它。
  • Call (invoking the function)调用（调用函数）: runs the code inside the function. In pseudocode: CALL name(args) or just name(args). In Python: name(args). The program jumps into the function body, executes it, then returns to where the call was., 运行函数内部的代码。伪代码：CALL name(args) 或直接 name(args)。Python：name(args)。程序跳入函数体，执行后返回调用处。
Execution flow: definition happens at load time (not run time). Each call jumps into the function, runs it to completion (or to a RETURN statement), then execution continues from the line after the call. AB CSE2110 outcome 3.2 says to "use appropriate types of subprograms … functions." Ontario ICS3U A3.2 says to "write subprograms … to perform tasks within programs."执行流程：定义在加载时发生（不是运行时）。每次调用跳入函数，运行到结束（或 RETURN 语句），然后继续执行调用之后的那行。AB CSE2110 结果 3.2 要求"使用适当类型的子程序……函数"。安大略 ICS3U A3.2 要求"编写子程序……在程序中执行任务"。
Worked Example 3: Defining and calling a greeting function例题 3：定义和调用问候函数

Problem: write a function that prints a greeting for a given name, then call it twice with different names.问题：编写一个函数，为给定姓名打印问候语，然后用不同姓名调用两次。

Pseudocode definition and calls.伪代码定义与调用。

FUNCTION greet(name):
    OUTPUT "Hello, " + name + "!"
END FUNCTION

CALL greet("Alice")
CALL greet("Bob")

伪代码说明：FUNCTION 定义函数，OUTPUT 输出，CALL 调用，name 为形参（parameter，形参）。Pseudocode: FUNCTION defines, OUTPUT prints, CALL invokes, name is the parameter.

Python rendering.Python 实现。

def greet(name):
    print("Hello, " + name + "!")

greet("Alice")   # Output: Hello, Alice!
greet("Bob")     # Output: Hello, Bob!

The def line defines the function; neither print runs until a call occurs. Each call creates a fresh execution of the function body, with the given argument bound to the parameter name.def 行定义函数；在调用发生之前，两次打印都不会运行。每次调用都会重新执行函数体，将给定的实参绑定到形参 name。

Worked Example 4: Order of definition and call例题 4：定义与调用的顺序

Problem: predict the output of the program below, tracing which line runs when. Then explain what goes wrong if the call announce() is moved above its definition.问题：预测下面程序的输出，并追踪每一行何时运行。然后解释如果把调用 announce() 移到它的定义上方会出什么问题。

Version A: predict the output.版本 A：预测输出。

def announce():
    print("start")
    greet("Cy")
    print("end")

def greet(name):
    print("Hi " + name)

announce()

Trace, one step at a time.逐步追踪。

  1. def announce() runs: Python stores the function under the name announce. Nothing is printed.def announce() 执行：Python 把函数存放在名称 announce 下。不输出任何内容。
  2. def greet(name) runs: stored the same way. Nothing is printed.def greet(name) 执行：以同样方式存放。不输出任何内容。
  3. announce() is called. Control jumps into its body and prints start.调用 announce()。控制权跳入其函数体并输出 start。
  4. Inside it, greet("Cy") is called, so name becomes "Cy" and Hi Cy is printed. greet finishes and control returns to the line after the call.在其中调用 greet("Cy")，于是 name 变为 "Cy"，输出 Hi Cy。greet 结束，控制权回到调用之后的那一行。
  5. announce prints end and finishes.announce 输出 end 并结束。

Output, in order: start, Hi Cy, end. Notice that greet is defined after announce in the file, yet the program works: announce only runs when it is called, and by then both definitions have executed.输出顺序：start、Hi Cy、end。注意 greet 在文件中定义在 announce 之后，程序仍然能运行：announce 只在被调用时才运行，而那时两个定义都已执行。

Version B: call before definition.版本 B：先调用后定义。

announce()          # called before the def line has run

def announce():
    print("start")

This stops with NameError: name 'announce' is not defined. When the first line runs, Python has not yet executed the def line, so the name does not exist. Fix: move the call below the definition. Why this works: def is a statement that creates the name when it executes; it is not a declaration read in advance.这会以 NameError: name 'announce' is not defined 终止。第一行执行时，Python 还没有执行 def 那一行，所以这个名称不存在。修复：把调用移到定义之下。原因：def 是一条在执行时才创建名称的语句，而不是提前读取的声明。

Common error: a mutable default argument.常见错误：可变的默认实参。

def add_item(item, bag=[]):      # the default list is created once
    bag.append(item)
    return bag

print(add_item("b"))   # ['a', 'b']   (surprise: 'a' is still there)

A default value is evaluated once, when the def line runs, not on every call. The first line printed ['a'] only because the list was empty at that point.默认值只在 def 行运行时计算一次，而不是每次调用都计算。因此空列表 [] 只创建一次，被所有省略 bag 的调用共用，所以第二次调用时 'a' 已经在里面了。第一行输出 ['a'] 只是因为那时列表是空的。

The fix: default to None.修复方法：默认值设为 None。

def add_item(item, bag=None):
    if bag is None:
        bag = []                 # a new list on every call
    bag.append(item)
    return bag

print(add_item("a"))   # ['a']
print(add_item("b"))   # ['b']

Now each call that omits bag builds its own new list, so the calls no longer affect each other. Python decides, before running a function, which names are local: any name that is assigned inside the function body is local for the whole body.   4. The waiting frames finish from the top down: fact(2) returns 2 * 1 = 2, fact(3) returns 3 * 2 = 6, fact(4) returns 4 * 6 = 24.等待中的帧从上到下依次完成：fact(2) 返回 2 * 1 = 2，fact(3) 返回 3 * 2 = 6，fact(4) 返回 4 * 6 = 24。

Four calls were made, so four frames were on the stack at the deepest point. The answer 24 equals 4 × 3 × 2 × 1.共进行了四次调用，所以在最深处栈上有四个帧。答案 24 等于 4 × 3 × 2 × 1。

Common error: forgetting the base case.常见错误：忘记基例。

# RecursionError: maximum recursion depth exceeded

Without the if n == 1 test, nothing ever stops the calls, the stack keeps growing, and Python stops the program with a RecursionError. A correct recursive function needs a base case that returns without recursing, and each recursive call must move closer to it (here n - 1 moves toward 1). This is also decomposition: fact(4) is solved by trusting a smaller call, fact(3).如果没有 if n == 1 这个判断，就没有任何东西能停止调用，栈不断增长，Python 会以 RecursionError 终止程序。正确的递归函数需要有一个不再递归就能返回的基例，并且每次递归调用都必须更接近基例（这里 n - 1 朝 1 靠近）。原因：每个帧都记住自己的 n 和待完成的乘法，所以在返回途中可以把各个答案组合起来。这也是分解：fact(4) 通过信任一个更小的调用 fact(3) 来解决。

Common Questions常见问题

What is the difference between a parameter and an argument?形参和实参有什么区别？

A parameter is the placeholder name written in the function definition, while an argument is the actual value you pass in when you call the function. The parameter has no value until the function is called with an argument.形参是写在函数定义中的占位符名称，实参是你调用函数时传入的实际值。在用实参调用函数之前，形参没有值。

What is the difference between a local and a global variable?局部变量和全局变量有什么区别？

A local variable is created inside a function, is only visible there, and is destroyed when the function returns, while a global variable is created outside all functions and is visible everywhere. Best practice is to prefer local variables and pass data in through parameters.局部变量在函数内部创建，只在该函数中可见，函数返回时被销毁；全局变量在所有函数之外创建，处处可见。最佳做法是优先使用局部变量，并通过参数传入数据。

Why should I use functions instead of repeating code?为什么要用函数而不是重复写代码？

Functions let you define logic once and call it anywhere, so there is no copy-paste, and if the logic changes you fix one place and every caller gets the update. They also support modular design by splitting a big program into small, independently testable pieces.函数让你只定义一次逻辑就能到处调用，无需复制粘贴；逻辑改动时只改一处，所有调用方都会得到更新。它们还支持模块化设计，把大程序拆成可独立测试的小块。
