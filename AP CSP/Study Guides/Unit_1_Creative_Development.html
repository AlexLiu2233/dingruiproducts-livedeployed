Topic 1.1
小节 1.1

Collaboration

协作

Must know
  • A computing innovation includes a program as an integral part of its function. It can be physical, software, or a computing concept. (CRD-1.A.1, CRD-1.A.2)
  • Effective collaboration combines diverse talents and perspectives; diverse perspectives also help avoid bias. (CRD-1.A.3, CRD-1.A.4)
  • Consulting users and gathering information from potential users help developers understand a program's purpose and incorporate diverse perspectives. (CRD-1.A.5, CRD-1.A.6)
  • Online tools let programmers share ideas and documents and provide feedback. (CRD-1.B.1)
  • Pair programming is a common model that facilitates collaboration. (CRD-1.B.2)
  • Effective teams practice communication, consensus building, conflict resolution, and negotiation. (CRD-1.C.1)
必备知识
  • 计算创新（computing innovation）的功能以程序为不可或缺的组成部分。它可以是实体、软件或计算概念。 (CRD-1.A.1, CRD-1.A.2)
  • 有效协作（collaboration）融合不同的才能和观点；多样化的观点也有助于避免偏见（bias）。 (CRD-1.A.3, CRD-1.A.4)
  • 咨询用户并向潜在用户收集信息，有助于开发者理解程序的目的并纳入多样化的观点。 (CRD-1.A.5, CRD-1.A.6)
  • 在线工具让程序员分享想法和文档，并提供反馈。 (CRD-1.B.1)
  • 结对编程（pair programming）是一种促进协作的常见模式。 (CRD-1.B.2)
  • 高效团队运用沟通、达成共识（consensus building）、解决冲突（conflict resolution）和协商（negotiation）等人际交往技能。 (CRD-1.C.1)

What collaboration improves

协作能带来什么改进

A self-driving car is a physical computing innovation, picture editing software is a nonphysical one, and e-commerce is a nonphysical computing concept. Each includes a program as an integral part of its function.

自动驾驶汽车是一种实体计算创新，图片编辑软件是一种非实体计算创新，电子商务则是一种非实体计算概念。它们的功能都以程序为不可或缺的组成部分。

People bring different talents and perspectives to a project. Consulting and communicating with users can reveal different views of a program's purpose. Developers can use that information to incorporate those views and help avoid bias.

项目成员会带来不同的才能和观点。咨询用户并与用户沟通，可以发现人们对程序目的的不同看法。开发者可以利用这些信息纳入不同观点，并帮助避免偏见。

How teams collaborate

团队如何协作

Teams can use online tools to share ideas and documents and give feedback. Pair programming is one model for working together. Team members also communicate, build consensus, resolve conflicts, and negotiate when they need to make decisions together.

团队可以使用在线工具分享想法和文档并给出反馈。结对编程是一种合作模式。需要共同做决定时，团队成员也要沟通、达成共识、解决冲突并进行协商。

Exam pattern: explain the improvement by connecting a specific perspective or feedback to a development decision, rather than just saying that teamwork is helpful.

考试常见思路：把具体的观点或反馈与开发决策联系起来，解释它如何带来改进，而不是只说团队合作有帮助。

Worked Example: Gathering User Perspectives例题：收集用户观点

A team is developing a picture editing program. One potential user wants simple controls; another wants more editing choices. Team members share both comments in an online document and disagree about what to include. How can collaboration improve the program?

一个团队正在开发图片编辑程序。一位潜在用户希望操作控件简单，另一位希望有更多编辑选项。团队成员在在线文档中分享了这两条意见，但对应该加入什么功能存在分歧。协作如何改进程序？

  1. Consulting different potential users reveals different views of the program's purpose: easy editing and access to more choices.
  2. The shared document lets team members review and provide feedback on both ideas.
  3. The members discuss the disagreement and negotiate a design with simple controls and additional editing choices, reaching consensus.
  4. Answer: The program can reflect both perspectives rather than only one group's preference. This helps the team avoid bias in its design.
  1. 咨询不同的潜在用户，可以发现他们对程序目的的不同看法：轻松编辑，以及使用更多选项。
  2. 共享文档让团队成员能够查看这两种想法并提供反馈。
  3. 成员讨论分歧，协商出同时提供简单控件和更多编辑选项的设计，并达成共识。
  4. 答案：程序可以体现这两种观点，而不是只体现某一类人的偏好。这有助于团队避免设计中的偏见。
Exam trap A classic wrong answer is that asking only the developers for their opinions is enough to represent users. Developers may miss user needs; consultation with potential users brings in perspectives the team might otherwise overlook.
考试陷阱 一个常见错误答案是：只询问开发者的意见就足以代表用户。开发者可能忽略用户需求；咨询潜在用户可以引入团队原本可能忽视的观点。
Going deeper Diverse perspectives help avoid bias, but collaboration alone does not guarantee an unbiased design. Consider whose feedback has been gathered and whether the resulting decisions actually incorporate it. Different user requests can conflict, so the team may need negotiation and consensus building.
深入理解 多样化的观点有助于避免偏见，但协作本身并不保证设计没有偏见。要考虑团队收集了哪些人的反馈，以及最终决策是否真正纳入了这些反馈。不同用户的要求可能互相冲突，因此团队可能需要协商并达成共识。

小节 1.2

Program Function and Purpose

程序的功能与目的

Must know
  • A computing innovation can solve a problem or pursue an interest through creative expression. Knowing its purpose helps developers build it. (CRD-2.A.1, CRD-2.A.2)
  • A program is a collection of statements that performs a task when run. A code segment is part of a program. A program needs to work for varied inputs and situations. (CRD-2.B.1, CRD-2.B.2, CRD-2.B.3)
  • Behavior is how a program functions during execution. Describe a program broadly by what it does, or in detail by also explaining how its statements do it. (CRD-2.B.4, CRD-2.B.5)
  • Input is data sent to a computer for processing. It can come from a user or another program and can be tactile, audio, visual, or text. Input usually affects output. (CRD-2.C.1, CRD-2.C.4, CRD-2.C.6)
  • An event is associated with an action and supplies input data. Events such as key presses, clicks, or program starts can affect execution. In event-driven programming, statements run when triggered rather than through sequential control flow. (CRD-2.C.2, CRD-2.C.3, CRD-2.C.5)
  • Output is data sent from a program to a device. It can be tactile, audio, visual, or text, and is usually based on input or prior state. (CRD-2.D.1, CRD-2.D.2)
必备知识
  • 计算创新（computing innovation）可以解决问题，也可以通过创意表达来追求兴趣。了解其目的有助于开发者进行开发。(CRD-2.A.1, CRD-2.A.2)
  • 程序（program）是计算机运行时执行特定任务的一组语句。代码段（code segment）是程序的一部分。程序需要适用于多种输入和情况。(CRD-2.B.1, CRD-2.B.2, CRD-2.B.3)
  • 行为（behavior）是程序执行时的运行方式。可以概括描述程序做什么，也可以进一步解释语句如何实现该功能。(CRD-2.B.4, CRD-2.B.5)
  • 输入（input）是发送给计算机、由程序处理的数据。输入可来自用户或其他程序，形式可以是触觉、音频、视觉或文本。输入通常会影响输出。(CRD-2.C.1, CRD-2.C.4, CRD-2.C.6)
  • 事件（event）与一个动作相关联，并向程序提供输入数据。按键、点击或程序启动等事件可以影响执行流程。在事件驱动编程（event-driven programming）中，语句由触发执行，而不是通过顺序控制流执行。(CRD-2.C.2, CRD-2.C.3, CRD-2.C.5)
  • 输出（output）是程序发送到设备的数据。输出可以是触觉、音频、视觉或文本形式，通常基于输入或先前状态。(CRD-2.D.1, CRD-2.D.2)

Purpose, function, and behavior

目的、功能与行为

Purpose explains why an innovation exists: it may address a problem or support creative expression. Understanding that purpose helps developers make decisions about what to build.

目的说明一项创新为何存在：它可能用于解决问题，也可能支持创意表达。理解目的有助于开发者决定要构建什么。

A program, often called software, is a collection of statements that performs a specific task when a computer runs it. A code segment is only part of a program. Behavior describes what happens during execution, often in terms of how a user interacts with the program.

程序通常也称为软件，是计算机运行时执行特定任务的一组语句。代码段只是程序的一部分。行为描述执行时发生的情况，通常结合用户如何与程序交互来说明。

Exam pattern: identify the input and output, then explain what the program does. For a detailed explanation, trace how the statements turn the input or prior state into the observed result. Consider more than one input or situation.

考试常见模式：先识别输入和输出，再解释程序做什么。需要详细说明时，追踪语句如何将输入或先前状态转化为观察到的结果。要考虑不止一种输入或情况。

Inputs, events, and outputs

输入、事件与输出

Input can come from a user or another program. An event is associated with an action and supplies input data. A key press, mouse click, program start, or another defined action can generate an event that affects execution. In event-driven programming, an event triggers statements instead of those statements simply running as part of a sequential flow.

输入可以来自用户或其他程序。事件与一个动作相关联，并提供输入数据。按键、鼠标点击、程序启动或其他已定义的动作都可以生成影响执行的事件。在事件驱动编程中，事件触发语句执行，而不是让这些语句仅作为顺序流程的一部分运行。

Both input and output can take forms such as text, visual, audio, or tactile data. Output goes from a program to a device. It is usually based on input or prior state, such as internal values, so it is not necessarily determined by the current input alone.

输入和输出都可以采用文本、视觉、音频或触觉等形式。输出从程序发送到设备。它通常基于输入或先前状态，例如内部数值，因此不一定只由当前输入决定。

Worked Example: Trace a doubling program例题：追踪倍数计算程序

A program is intended to help a user find twice a number. The user enters 7. Identify the input and output, and explain how the program works.

一个程序旨在帮助用户求出一个数的两倍。用户输入 7。请识别输入和输出，并解释程序如何运行。

number ← INPUT()
result ← number * 2
DISPLAY(result)
  1. INPUT() accepts 7, so the input is 7 and number becomes 7.
  2. The second statement multiplies 7 by 2 and stores 14 in result.
  3. DISPLAY(result) displays 14 followed by a space. That displayed value is the output.
  4. Answer: the program doubles the input by storing twice its value and displaying the result. For input 0, it displays 0 followed by a space instead.
  1. INPUT() 接收 7，因此输入是 7，number 的值变为 7。
  2. 第二条语句将 7 乘以 2，并把 14 存入 result。
  3. DISPLAY(result) 显示 14，后面带一个空格。显示的值就是输出。
  4. 答案：程序通过存储输入值的两倍并显示结果，来实现倍数计算。若输入为 0，则显示 0，后面带一个空格。
Exam trap

Do not call an internal value an output just because the program calculated it. In the example, result is an internal value; it becomes displayed output when DISPLAY sends its value to a device. Also, “it doubles a number” describes what the program does, not how its statements accomplish it.

考试陷阱

不要仅因为程序计算出了某个内部值，就把它称为输出。例题中的 result 是内部值；当 DISPLAY 将其值发送到设备时，它才成为显示输出。另外，“它将一个数翻倍”说明的是程序做什么，并未解释语句如何实现这一功能。

Going deeper

One successful input does not establish that a program works in every relevant situation. Trace different inputs and consider prior state when predicting output. Two runs with the same current input can produce different outputs if the program uses different prior internal values.

深入理解

一个输入得到正确结果，并不能证明程序在所有相关情况下都能正常运行。预测输出时，应追踪不同输入并考虑先前状态。如果程序使用的先前内部值不同，两次运行即使当前输入相同，输出也可能不同。

Program Design and Development

程序设计与开发

Must know
  • Development can be ordered or exploratory. Common phases include investigation and reflection, design, prototyping, and testing. Iterative development revises work; incremental development builds working pieces into a whole. (CRD-2.E.1, CRD-2.E.2, CRD-2.E.3, CRD-2.E.4)
  • Investigate requirements, constraints, and users’ concerns and interests through surveys, user testing, interviews, or direct observations. (CRD-2.F.1, CRD-2.F.2, CRD-2.F.3)
  • A specification defines requirements. Design outlines how to meet it, including possible interface layouts and a testing strategy. (CRD-2.F.4, CRD-2.F.5, CRD-2.F.6, CRD-2.F.7)
  • Document function and development throughout the process. Comments are documentation for people and do not affect execution; other documentation may be needed. (CRD-2.G.1, CRD-2.G.2, CRD-2.G.3, CRD-2.G.4, CRD-2.G.5)
  • Acknowledge collaborative or externally sourced code. Documentation can credit its origin or original author. (CRD-2.H.1, CRD-2.H.2)
必备知识
  • 开发可以有序进行，也可以采用探索方式。常见阶段包括调查与反思、设计、原型制作和测试。迭代开发（iterative development）反复修改；增量开发（incremental development）将可运行的小部分逐步加入整体。（CRD-2.E.1, CRD-2.E.2, CRD-2.E.3, CRD-2.E.4）
  • 通过问卷、用户测试、访谈或直接观察，调查需求、约束以及用户的顾虑和兴趣。（CRD-2.F.1, CRD-2.F.2, CRD-2.F.3）
  • 规格说明（specification）定义需求。设计概述如何满足规格，可包括界面布局和测试策略。（CRD-2.F.4, CRD-2.F.5, CRD-2.F.6, CRD-2.F.7）
  • 在整个开发过程中记录程序功能和开发过程。注释（comments）是供人阅读的文档，不影响程序运行；有时需要其他文档方式。（CRD-2.G.1, CRD-2.G.2, CRD-2.G.3, CRD-2.G.4, CRD-2.G.5）
  • 应注明协作编写或来自外部的代码。可以在文档中注明其来源或原作者。（CRD-2.H.1, CRD-2.H.2）

Development processes

开发过程

There is more than one development process. A team may follow an ordered, intentional approach or explore ideas as it works. Common phases are investigating and reflecting, designing, prototyping, and testing. An iterative process uses feedback, testing, or reflection to refine work throughout development and may return to an earlier phase.

开发过程不止一种。团队可以按有序、有计划的方式进行，也可以边开发边探索想法。常见阶段有调查与反思、设计、制作原型（prototyping）和测试。迭代过程在整个开发中利用反馈、测试或反思来改进成果，并可能返回先前的阶段。

An incremental process breaks a problem into smaller pieces and checks that each piece works before adding it to the whole. For exam questions, distinguish revising existing work from adding a working piece. A process can do both.

增量过程把问题拆成较小的部分，确保每部分能正常工作后再将其加入整体。考试中要区分修改已有成果和加入可运行的部分。一个过程可以同时采用这两种方式。

Investigation and design

调查与设计

Investigation helps identify requirements, constraints, and the concerns and interests of intended users. Developers can collect survey data, conduct user tests or interviews, and make direct observations. Requirements describe how a program functions and may describe interactions it must provide. The specification defines those requirements.

调查有助于确定需求、约束（constraints）以及目标用户的顾虑和兴趣。开发者可以收集问卷数据、进行用户测试或访谈，也可以直接观察。需求描述程序如何运行，也可能描述程序必须提供的用户交互。规格说明定义这些需求。

Design outlines how to meet the specification. It may include brainstorming, planning and storyboarding, organizing modules and functional components, drawing user-interface layouts, and developing a testing strategy.

设计概述如何满足规格说明。设计可包括头脑风暴、规划和制作分镜（storyboarding）、组织模块与功能组件、绘制用户界面（user interface）布局图，以及制定测试策略。

Documentation and acknowledgment

文档与代码来源说明

Program documentation is a written description of the function of a code segment, event, procedure, or program and how it was developed. Write it throughout development. It helps individuals and teams develop and maintain correct programs. Comments are written into a program for people to read; they do not affect how it runs. Some environments do not support comments, so documentation may need to be kept another way.

程序文档（program documentation）是对代码段、事件、过程（procedure）或程序的功能及其开发方式的书面描述。应在整个开发过程中编写文档。文档有助于个人和团队开发、维护正确的程序。注释写在程序中，供人阅读，不影响程序运行。有些环境不支持注释，因此可能需要用其他方式保存文档。

Acknowledge code developed collaboratively or obtained from another source. For code written by someone else, the documentation can identify its origin or original author.

应注明协作开发或来自其他来源的代码。对于他人编写的代码，可以在文档中注明其来源或原作者。

Worked Example: Designing a doubling program例题：设计一个将数值翻倍的程序

A team investigates a program for users who want to enter a number and see twice its value. The specification requires a numeric input and a displayed result. Teammate Lin wrote the display calculation in this prototype:

某团队调查一个程序：用户希望输入一个数并看到它的两倍。规格说明要求输入数值并显示结果。队友 Lin 编写了这个原型中的显示计算部分：

number ← INPUT()
DISPLAY(number * 2)
  1. Design the interaction: provide a way to enter a number and a place to show the result. Plan a test with input 3 and expected value 6.
  2. Trace the prototype: INPUT() supplies 3, so number * 2 is 6. The program displays 6 followed by a space.
  3. If user testing shows that the interaction is unclear, revise the interface design and test again. This is iteration. Building and checking another required piece before adding it would be incremental development.
  4. Document that the program takes a number and displays twice its value, describe how it was developed, and credit Lin for the display calculation. Answer: the prototype produces the expected value 6 for this test.
  1. 设计交互：提供输入数值的方式和显示结果的位置。计划用输入 3 测试，预期结果为 6。
  2. 跟踪原型：INPUT() 提供 3，因此 number * 2 为 6。程序显示 6，后面带一个空格。
  3. 如果用户测试表明交互不够清晰，就修改界面设计并再次测试。这是迭代。先构建并检查另一个所需部分，再把它加入程序，则是增量开发。
  4. 记录程序接收一个数并显示其两倍，描述开发过程，并注明显示计算部分由 Lin 编写。答案：该原型在此测试中产生预期值 6。
Exam trap

“Iterative” does not simply mean adding features one at a time. That describes incremental development when each piece is checked before integration. Iteration means refining and revising based on feedback, testing, or reflection.

考试陷阱

“迭代”不只是一次添加一个功能。如果每个部分在整合前都经过检查，这描述的是增量开发。迭代是根据反馈、测试或反思进行改进和修改。

Going deeper

A successful test of one input does not establish that the entire program is correct. Compare test results with the specification, and use user feedback to decide whether to revisit the design. Keep documentation and code credits up to date as the program changes, even if the environment does not support comments.

深入理解

一个输入的测试成功，并不能证明整个程序都正确。应将测试结果与规格说明比较，并利用用户反馈决定是否重新审视设计。即使环境不支持注释，也要随着程序变化及时更新文档和代码来源说明。

Identifying and Correcting Errors

识别与纠正错误

Must know
  • A logic error causes incorrect or unexpected behavior; a syntax error breaks a programming language rule. (CRD-2.I.1, CRD-2.I.2)
  • A run-time error occurs during execution; an overflow error occurs when a number is outside a defined range. (CRD-2.I.3, CRD-2.I.4)
  • Find and correct errors using test cases, hand tracing, visualizations, debuggers, or extra output statements. (CRD-2.I.5)
  • Use requirements to choose test inputs and expected outcomes, then use the results to revise the program. (CRD-2.J.1, CRD-2.J.3)
  • Test inputs at and just beyond the minimum and maximum to check different expected outcomes. (CRD-2.J.2)
必备知识
  • 逻辑错误（logic error）会导致不正确或意外的行为；语法错误（syntax error）违反编程语言的规则。(CRD-2.I.1, CRD-2.I.2)
  • 运行时错误（run-time error）在程序执行期间发生；溢出错误（overflow error）发生在数值超出规定范围时。(CRD-2.I.3, CRD-2.I.4)
  • 可使用测试用例（test cases）、手动追踪（hand tracing）、可视化、调试器（debuggers）或额外输出语句来查找并纠正错误。(CRD-2.I.5)
  • 依据程序要求选择测试输入和预期结果，再利用测试结果修改程序。(CRD-2.J.1, CRD-2.J.3)
  • 测试最小值、最大值及刚好超出两端的输入，检查不同的预期结果。(CRD-2.J.2)

Recognize the error

识别错误

A program can follow the language rules and still have a logic error. Compare what it does with what the requirements say it should do. A syntax error instead violates a language rule. A run-time error happens while the program is running; programming languages define their own run-time errors.

程序即使遵守语言规则，仍可能有逻辑错误。应比较程序的实际行为和要求中的预期行为。语法错误则是违反语言规则。运行时错误发生在程序运行期间；不同编程语言会定义各自的运行时错误。

Overflow concerns a number outside a computer's defined range of values. It is different from a logic error such as using the wrong comparison.

溢出指计算机处理的数值超出其规定的取值范围。它不同于使用错误比较条件这类逻辑错误。

Test, trace, and revise

测试、追踪与修改

Exam pattern: start with the requirements, choose inputs and their expected outcomes, then trace or run the program and compare. If an outcome differs, locate the error, revise the program, and test again. Hand tracing tracks values step by step. Visualizations, debuggers, and extra output statements can also help reveal what happens during execution.

考试常见方法：先看程序要求，选择输入及其预期结果，再追踪或运行程序并进行比较。如果结果不同，就定位错误、修改程序并再次测试。手动追踪会逐步记录数值；可视化、调试器和额外输出语句也有助于观察执行过程。

Worked Example: Test a boundary例题：测试边界

A program must accept integer inputs from 1 through 10, inclusive, and reject other integers. Identify and correct the error.

某程序必须接受从 1 到 10（包含两端）的整数输入，并拒绝其他整数。请识别并纠正错误。

n ← INPUT()
IF(n > 1 AND n ≤ 10)
{
  DISPLAY("accepted")
}
ELSE
{
  DISPLAY("rejected")
}
  1. From the requirements, inputs 1 and 10 should display accepted; inputs 0 and 11 should display rejected.
  2. Trace input 1: n > 1 is false, so the program displays rejected. This differs from the expected result.
  3. The lower-bound comparison is a logic error. Replace n > 1 with n ≥ 1.
  4. With that correction, inputs 1 and 10 are accepted, while 0 and 11 are rejected. The corrected condition is n ≥ 1 AND n ≤ 10.
  1. 根据要求，输入 1 和 10 应显示 accepted；输入 0 和 11 应显示 rejected。
  2. 追踪输入 1：n > 1 为假，因此程序显示 rejected，与预期结果不同。
  3. 下界比较存在逻辑错误。将 n > 1 改为 n ≥ 1。
  4. 修改后，输入 1 和 10 被接受，0 和 11 被拒绝。正确条件是 n ≥ 1 AND n ≤ 10。
Exam trap

Wrong answer: “The program has no error because it runs.” A program can run but still produce the wrong result. Compare its behavior with the requirements, especially at the boundaries.

考试陷阱

错误答案：“程序能运行，所以没有错误。”程序即使能运行，也可能产生错误结果。要将实际行为与要求比较，尤其要检查边界。

Going deeper

Passing the boundary tests does not prove every input is correct. Also test an input inside the range, such as 2, and compare its result with the required outcome. After any revision, rerun relevant tests to check the change.

深入理解

通过边界测试并不能证明所有输入的结果都正确。还应测试范围内的输入，例如 2，并将结果与要求比较。每次修改后，重新运行相关测试以检查改动。

Unit 1 MCQ Patterns That Show Up Every Year

单元 1 每年都会出现的选择题套路

Creative Development accounts for 10–13% of the multiple-choice exam. Questions may ask you to evaluate collaboration, distinguish program purpose from behavior, or choose development and testing practices.

创造性开发（Creative Development）约占选择题的 10%–13%。题目可能要求你评估协作、区分程序目的与行为，或选择合适的开发和测试方法。

Pattern 1: Value diverse perspectives When a team is designing for users, look for consultation and feedback from people with different perspectives. These can reveal needs and reduce bias, though they do not guarantee its elimination. (See Topic 1.1.)
套路 1：重视多元视角 当团队为用户设计程序时，优先考虑向不同视角的人咨询并收集反馈。这有助于发现需求、减少偏见，但不能保证彻底消除偏见。（参见主题 1.1。）
Pattern 2: Separate purpose, input, and output Identify the problem or interest as the purpose, data sent to the program as input, and data sent to a device as output. An event can trigger statements and supply input. (See Topic 1.2.)
套路 2：区分目的、输入和输出 将程序要解决的问题或满足的兴趣看作目的；发送给程序的数据是输入，程序发送到设备的数据是输出。事件（event）可以触发语句并提供输入。（参见主题 1.2。）
Pattern 3: Distinguish development processes Revising based on feedback or testing is iterative; building and checking smaller pieces before adding them to the whole is incremental. A process can use both approaches. (See Topic 1.3.)
套路 3：区分开发过程 根据反馈或测试结果反复修改属于迭代式开发（iterative development）；先构建并检查小部分，再将其加入整体，属于增量式开发（incremental development）。一个过程可以同时采用两种方法。（参见主题 1.3。）
Pattern 4: Document and credit code Comments explain code to people and do not change how it runs. Documentation can also credit collaboratively developed or external code by naming its origin or author. (See Topic 1.3.)
套路 4：编写文档并注明代码来源 注释（comment）供人阅读，不会改变程序运行方式。文档（documentation）还可以通过注明来源或作者，确认协作编写或外部代码的贡献。（参见主题 1.3。）
Pattern 5: Test boundaries and trace errors Use requirements to choose inputs at and just beyond allowed extremes, then compare actual and expected behavior. Trace the program to locate logic errors; distinguish them from syntax and run-time errors. (See Topic 1.4.)
套路 5：测试边界并追踪错误 根据需求选择位于允许范围边界及刚好超出边界的输入，再比较实际行为与预期行为。通过手动追踪（hand tracing）定位逻辑错误，并将其与语法错误和运行时错误区分开。（参见主题 1.4。）

What makes something a computing innovation?什么使一项创新成为计算创新（computing innovation）？
A program is an integral part of its function. It can be physical, software, or a computing concept.程序是其功能不可或缺的一部分。它可以是实体、软件或计算概念。
How can diverse collaboration improve a computing innovation?多元协作如何改进计算创新（computing innovation）？
Different talents and user perspectives can reveal needs and help reduce bias.不同的才能和用户视角有助于发现需求并减少偏见。
What practices support effective collaboration?哪些做法有助于有效协作？
Communication, consensus building, conflict resolution, negotiation, and shared tools or pair programming.沟通、达成共识、解决冲突、协商，以及使用共享工具或结对编程（pair programming）。
How do a program's purpose and behavior differ?程序的目的（purpose）与行为（behavior）有何区别？
Purpose is the problem or interest it addresses; behavior is how it functions during execution.目的是程序要解决的问题或满足的兴趣；行为是程序执行时如何运行。
What are program inputs and outputs?什么是程序的输入（input）和输出（output）？
Inputs are data sent to a computer for processing; outputs are data sent from a program to a device.输入是发送给计算机供程序处理的数据；输出是程序发送到设备的数据。
What is an event in event-driven programming?在事件驱动编程（event-driven programming）中，什么是事件（event）？
Something associated with an action that supplies input data and can trigger program statements, such as a key press or mouse click.与某个动作相关联、向程序提供输入数据并可触发程序语句执行的发生项，例如按键或鼠标点击。
How do iterative and incremental development differ?迭代式开发（iterative development）与增量式开发（incremental development）有何区别？
Iterative development revises using feedback, testing, or reflection; incremental development builds and checks smaller pieces before combining them.迭代式开发利用反馈、测试或反思进行修改；增量式开发先构建并检查小部分，再将其组合。
What are program requirements and a specification?什么是程序需求（requirements）和规格说明（specification）？
Requirements describe how a program should function and may describe user interactions; a specification defines those requirements.需求描述程序应如何运行，也可能描述用户交互；规格说明定义这些需求。
Why document a program and acknowledge borrowed code?为什么要编写程序文档（documentation）并注明借用代码的来源？
Documentation supports development and maintenance; credit identifies the origin or original author of code from others.文档有助于开发和维护；注明来源可以表明他人代码的出处或原作者。
How do logic, syntax, and run-time errors differ?逻辑错误（logic error）、语法错误（syntax error）和运行时错误（run-time error）有何区别？
A logic error causes incorrect behavior; a syntax error breaks language rules; a run-time error occurs during execution.逻辑错误导致行为不正确；语法错误违反语言规则；运行时错误在程序执行期间发生。
What is an overflow error?什么是溢出错误（overflow error）？
An error caused by attempting to handle a number outside the defined range of values.尝试处理超出定义数值范围的数字时发生的错误。
How should test inputs be chosen?应如何选择测试输入（test inputs）？
Use requirements to select inputs with expected outcomes, including values at and just beyond the minimum and maximum.根据需求选择具有预期结果的输入，包括最小值、最大值及刚好超出边界的值。
